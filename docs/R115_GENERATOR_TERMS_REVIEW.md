# R115 generator-terms and provenance review

**Status:** review record, updated 2026-10-24 (external sources accessed that day). **Not legal
advice.** Retaining R115 is an engineering/project decision (Option A), **not legal clearance and
not proof of permission**. Documenting a risk does not resolve it. Protocol v5
(`docs/protocol_v5.json`, SHA-256 `3889099d1da7fa6cdc987685a2dacda4592508339bd8cedb91a99fa29f25f3ee`)
is unchanged by this review.

Evidence classes used below: **[repo]** verified from files in this repository; **[source]**
stated in an authoritative external document (accessed 2026-10-24); **[unverifiable]** could not be
established from available evidence; **[decision]** a project decision.

## 1. What R115 contributes

- **[repo]** Dataset `Ridham115/indian-scam-sms-synthetic-audited`, revision
  `45e92c38ba20e973ef3ff5d1893a0a710f622018`, file `synthetic_audited.csv`, SHA-256
  `45bde5f156a1a42698bab209e32bcd41b3639013d772f644cc3208ed39fb61e2` (matches protocol v5
  `sources.R115.file_sha256`). 1,580 rows: `groq/openai/gpt-oss-120b` 700 (357 scam, 343 safe),
  `gemini/gemini-3.5-flash-lite` 861, `gemini/gemini-3.7-flash` 19.
- **[repo]** The v5 builder (`v3.load_r115`) keeps only rows whose `generator` is in
  `sources.R115.generators_used` (`groq/openai/gpt-oss-120b`): 700 rows kept, 880 Gemini rows
  excluded as `excluded_generator`. Labels map scam→suspicious, safe→legitimate. R115 is
  training-only (never test-eligible).
- **[repo]** v5 dry run (`reports/build_v5/build_report_dry_run.json`): 696 R115 rows in the pool
  (353 suspicious, 343 legitimate; 4 purged as near-duplicates of test rows), in 39 grouping units.
  That is 6.2 % of the 11,251 pool rows, **28.5 % of the 1,203 legitimate pool rows** and 3.5 % of
  the 10,048 suspicious pool rows.
- **[repo]** R115 gpt-oss rows are also in training pool v2 and therefore in candidate v2 (not
  deployed). The deployed v1 model was trained only on `synthetic_financial_messages_v1`.
- **[repo]** No code in this repository calls Groq, OpenAI or Gemini; the generator name appears
  only as a filter value.
- **[source]** The dataset card's intended use, "Training and stress-testing scam or phishing
  classifiers as a *supplement* to real data … Not for evaluating deployed systems", matches the
  project's use (training supplement, never in the test). The card also states that labels were
  audited mostly by an AI assistant with a partial human check, and that most rows were not read.

## 2. Licence and attribution

- **[source]** Declared licence **CC BY 4.0** (card front matter `license: cc-by-4.0`; Hugging Face

- **[source]** CC BY 4.0 §3(a)(1) applies "If You Share the Licensed Material (including in
  modified form)". It requires keeping, if supplied, creator identification "in any reasonable
  manner requested by the Licensor", a copyright notice, licence and disclaimer notices and "a URI
  or hyperlink to the Licensed Material", indicating modifications (§3(a)(1)(B)), and indicating
  the CC BY 4.0 licence with its text or URI (§3(a)(1)(C)).
- **[source]** Creator: Hugging Face account `Ridham115`. No copyright notice is supplied. Citation
  request: "please link the repository and the AI Scam & Phishing Message Detector project that
  produced it". No URL is given for that project.
- **[repo] Protocol gap, closed in the provenance output.** Protocol v5's R115 entry has `title`
  ("… (CC BY 4.0)"), `revision` and `file_sha256`, but no `licence` or `attribution` field (IMC25
  and MENDELEY have both); the pinned protocol is unchanged. The v5 builder

  below and an explicit "NOT VERIFIED" note on upstream generator terms to the pool provenance,

  the pool are unaffected (tests: `tests/test_build_v5.py::TestProvenanceAttribution`).
- **[repo]** SatyaLens does not currently share R115 records: the training pool is gitignored and
  committed reports contain counts only.
- **Attribution to use whenever R115 material is shared** (proposed text):
  > Ridham115, "Indian Scam SMS (synthetic, audited)", Hugging Face dataset
  > `Ridham115/indian-scam-sms-synthetic-audited`, revision `45e92c38ba20e973ef3ff5d1893a0a710f622018`,

## 4. Assessment (a reading of the documents, not a legal conclusion)

1. Groq's Agreement and AUP bind Groq's customer, here the dataset author. SatyaLens is not a
   Groq customer for R115. Under the current §8.1 the author holds the Output IP and could license
   it under CC BY 4.0. No reviewed term restricts SatyaLens's own use of the retained rows as
   training data.
2. The gpt-oss licence and usage policy govern use of the model, not its outputs.
3. There is no evidence that a violation occurred. There is also no evidence that the author's
   generation of phishing-style text was permitted (research exception or otherwise).

## 6. Decision and residual risks

**[decision] 2026-10-24: Option A.** R115 (gpt-oss-120b rows only) is retained under protocol v5
unchanged. This is an engineering/project decision taken under time constraints. It is **not
legal clearance**, the author's permissions were **not verified**, and the only verified grant to
SatyaLens is the dataset's declared CC BY 4.0 licence.

Residual risks accepted with this decision:
- If U1 resolves unfavourably, models trained on pool v5 (and candidate v2) include data whose
  generation may have breached the provider's AUP. Removing it would need protocol v6, a new pool
  and a reseal, and would remove 28.5 % of the legitimate training rows.
- U2 cannot be closed from published material.
- The protocol v5 R115 entry has no attribution field (U3); attribution is carried by the pool
  provenance and this document.
- Data-quality limits stated by the dataset card (AI-assisted labels, mostly unread rows, label
  shortcuts) apply.

## 7. Future actions (when time permits)

1. Ask the dataset author for the generation date, whether a Groq research exception or other
   permission was held, and the URL of the requested project link; record the answer here.
2. Ask Groq which AUP version applied on the generation date, if the author cannot answer.
3. Before any external release (dataset, pool or model trained on R115): obtain legal review of
   U1 and U3, and include the §2 attribution in the release notes.
4. In the next protocol version, add `licence` and `attribution` fields to `sources.R115` (and to
   the other sources that lack them) and retire the builder's `PROVENANCE_SUPPLEMENT`.
5. If U1 resolves unfavourably, prepare protocol v6 without R115 (training pool and reseal only;
   frozen-test membership would not change, since R115 is never test-eligible).

## Options considered

| Option | Effect |
|---|---|
| A. Proceed under protocol v5 as written **(chosen)** | Declared CC BY 4.0 licence; U1–U3 stay open residual risks. |
| B. Ask the dataset author before sealing | Could resolve U1/U2 if answered; delays sealing. Not chosen (time). |
| C. Exclude R115 | Needs protocol v6; pool, pool SHA-256 and `pool_counts` change; frozen-test membership does not (R115 ranks below every test-eligible source in dedup priority). |
