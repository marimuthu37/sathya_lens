# Dataset card — satyalens-synthetic-submission v1.0.0

## Summary
518 synthetic records for testing the two workflows SatyaLens implements:
financial **message text** (336 records) and **payment screenshots** with
optional user-supplied expected payment details (182 records, PNG). Generated by
`generate_dataset.py`, seed `20261025`. Licence: same as the SatyaLens project
(all content is generated; no third-party data).

## Intended use
- Regression and behaviour testing of the SatyaLens pipeline.
- Demonstrating, reproducibly, what the pipeline flags and what it withholds.

**Not** for: claiming real-world detection rates, training a production model,
or benchmarking against real fraud data.

## Record structure
| Block | Content | Visible to the system under test? |
|---|---|---|
| `input` | `message_text`, or `image_path` + `expected_payment`; `media_type` | **Yes — only this** |
| `ground_truth` | `label`, `rationale`; for screenshots `expected_field_status` and `rendered` values | No (evaluation only) |
| `meta` | `split`, `category`, `template_family`, `template_id`, `scenario_id`, render parameters, image SHA-256 | No (evaluation only) |

`expected_payment` is part of the input on purpose: SatyaLens asks the user
what they expected to pay, and compares it with the screenshot.

## Labels
| Modality | Label | Meaning (expected SatyaLens behaviour) |
|---|---|---|
| message_text | `suspicious` | should be flagged (Verify First) |
| | `legitimate` | should not be flagged; includes hard negatives using alarming words |
| | `ambiguous` | either outcome defensible; reported, not scored |
| payment_screenshot | `discrepancy` | conflicts with user expectations or shows a placeholder recipient → Verify First |
| | `consistent` | matches expectations, differs only in formatting, or no expectations given → not flagged, never "genuine" |
| | `insufficient_evidence` | cannot be checked (degraded, unreadable, field missing) → comparisons withheld, never Low Concern |

Categories and their per-category rules are listed in `manifest.label_rules`
and `docs/generation_methodology.md`.

## Composition (records per split)
| | train | dev | test |
|---|---|---|---|
| messages: 14 categories × 1 template × 8 variants | 112 | 112 | 112 |
| screenshots: 13 categories × 4/4/6 | 52 | 52 | 78 |

Suspicious categories: account_block_urgency, otp_request, kyc_link,
fake_payment_claim, fee_or_prize_demand, impersonation_money. Legitimate:
otp_delivery, transaction_alert, bill_reminder, delivery_update,
security_advisory, everyday_money_talk. Ambiguous: unverified_payment_request,
unclear_account_notice.

Screenshot categories: consistent, amount_format_only, reference_format_only,
no_expected_values, amount_mismatch, currency_mismatch, recipient_mismatch,
reference_mismatch, placeholder_recipient, missing_recipient, degraded_blur,
degraded_lowres, unreadable. Layouts: rows, receipt, stacked, card; fonts:
Arial, Verdana, Georgia, Calibri, Segoe UI, Times New Roman.

## Privacy
No real personal data. Banks are fictional ("Kaveri Demo Bank"); links use the
reserved `.example` domain; phone numbers, OTPs, UPI handles and references are
random digits; merchants and people are invented names.

## Not covered
Audio (SatyaLens audio detection unavailable), webpages/phishing pages (not
implemented), multilingual or code-mixed text, real screenshots from banking
apps, image tampering/forgery detection.
